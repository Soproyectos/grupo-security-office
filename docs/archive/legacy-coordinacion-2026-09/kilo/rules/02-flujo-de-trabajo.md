# Flujo de trabajo obligatorio

Para cada tarea:

1. Leer reglas y contexto del proyecto.
2. Inspeccionar el código antes de proponer cambios.
3. Resumir objetivo, archivos afectados, riesgos y plan.
4. Esperar aprobación humana antes de cambios con impacto alto:
   - migraciones,
   - eliminación de datos,
   - cambios de permisos,
   - cambios de roles,
   - cambios de APIs públicas,
   - alteraciones de comportamiento existente.
5. Implementar solo la tarea aprobada.
6. Ejecutar pruebas, lint y build disponibles.
7. Informar resultado, archivos modificados, comandos ejecutados, pruebas, riesgos y siguiente tarea recomendada.
8. Actualizar el backlog o las decisiones cuando corresponda.
